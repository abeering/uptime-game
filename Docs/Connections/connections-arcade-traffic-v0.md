# Connections Arcade V1 — traffic generation V0

**Ambient Traffic Director restructure (PR #40, October 26, 2026):** The additive mixed-plus-coverage model described below has been replaced. One `ConnectionTrafficDirector` now runs two seeded processes: benign coverage is the only ordinary benign producer, and hostiles have an independent exponential arrival clock with a 54-second mean. The former fixed 13.5 ± 1.5-second mixed scheduler and 25% hostile roll are removed. The benign stream uses the 1→3 goal ramp over 75 seconds, an 8-second mean opportunity interval, a 12% chance at or above its effective goal, established/near-term population feedback, and cancellation-aware Blackout recovery. The hostile stream selects a weighted canonical PURPOSE, then uses the existing LOADER/DELIVERY, anomaly, infection, and concrete plan machinery. Separate seeded streams govern benign and hostile scheduling and plan sampling; `HostileGenerationEnabled` disables the hostile stream for isolated tests, and `AutoGenerationEnabled` gates both. Run logs distinguish `ambient_benign` from `ambient_hostile` and record both opportunity schedules. Manual and Spawner plans still use the same queue and lifecycle. The [review measurements](../Review/ConnectionsAmbientPopulationV1/README.md) cover four fixed seeds, healthy and hostile-enabled, over 600 seconds. All tuning is provisional for the four-node scene. Older phase descriptions below preserve their original baselines.

**Superseded Population / Coverage V1 playtest amendment (October 26, 2026):** The first PR #40 implementation below spawned at every supplemental opportunity and could surge above its goal at startup. The scene now ramps the effective benign goal from 1 to 3 over 75 simulated seconds. An opportunity uses established plus Connecting, Pending, and queued benign plans scheduled within five seconds; it samples a separate coverage-stream roll with a 4% spawn chance at or above the effective goal and a rising chance below it. This is a soft response, not a cap. During Blackout, recent benign cancellations also weigh against selection, and the retry interval is bounded to 20 seconds. Cleaning the last Blackout clears cancellation pressure and pulls the next opportunity within about one simulated second. The recorder logs effective goal, chance, roll, counts, and next schedule; metadata logs the configuration. All values are provisional playtest tuning. The original ordinary stream and its hostile rolls remain unchanged. The [review evidence](../Review/ConnectionsAmbientPopulationV1/README.md) compares deterministic opening windows and a 600-second healthy run.

**Superseded Population / Coverage V1 first implementation (October 26, 2026):** Generated mode retains the 3-second grace and the original 13.5 ± 1.5-second ambient stream, including its unchanged 25% hostile roll. A separate benign-only opportunity stream now uses a soft established-population goal of 3. Its Inspector mean interval is 10 seconds at the goal, with a 0.6 exponential response to the current established benign count plus queued, pending, and Connecting benign plans. Each wait is sampled from an exponential distribution using a seed-derived random stream distinct from ordinary ambient, Spawner, and ID draws. It can produce close arrivals, long lulls, and crowding; it has no hard minimum or cap. A recent benign cancellation counts as two units of temporary scheduling pressure for 60 seconds, easing repeated failed top-ups during Blackout without hiding or rerouting physically valid attempts. These are provisional tuning values for the four-node scene, not general balance rules.

Coverage selects only positively weighted canonical PURPOSE templates, with the same eligible-target, route, normal LOAD/WORK, operation, and benign-outlier machinery as ordinary generation. It never rolls a hostile objective. Its `plan_queued.source` is `ambient_coverage`; the existing stream remains `ambient`. The recorder stores the four coverage settings, the fixed cancellation weight, each opportunity's established/anticipated/recent-canceled counts, derived mean and sampled next interval, and established benign/hostile snapshot counts. `AutoGenerationEnabled` gates both ambient streams, while manual and Spawner plans still dispatch. The original stream's random decisions and cadence remain isolated; extra plans necessarily use IDs and can alter subsequent network outcomes. Long unattended Blackouts can still leave benign occupancy near zero, because no coverage controller can establish a connection on an unavailable route. This phase does not change WORK rate, threat recipes, resource allocation, Health rules, or topology.

**Play seed option:** The Connections scene now authors **Randomize Seed** as checked on `ConnectionTrafficDirector`. At Play start, the host asks the director to select a new seed before resetting generation and starting the recorder. The selected seed is shown in the Inspector and saved in run metadata and filename. Later simulation resets within the same Play session replay that seed. Unchecking the option uses the Inspector's fixed Seed value (1701 in the scene) for repeatable runs. The random choice uses a separate source, leaving each chosen seed's traffic, Spawner, and ID streams deterministic.

**Generated Hostile Traffic V0 update (October 24, 2026):** The original benign-only and later manual-only passages below preserve their phase provenance. Current Generated mode selects all ten built-in profiles from one ambient scheduler. The five ordinary weights remain `1, 0.8, 1, 0.8, 0.35` (3.95 total); added weights are `basic-threat: 0.42`, `delayed-threat: 0.37`, `spiking-threat: 0.26`, `spiking-benign: 0.16`, and `overload-demo: 0.11` (5.27 total). The ordinary share is about 75%; the five additions are provisional playtest tuning, not balance rules. Scene cadence remains 3 s grace, 13.5 s interval, ±1.5 s jitter. All operation definitions, behavior timing, WORK/LOAD rules, effects, and internal classification remain unchanged.

The director's **Ambient Weight Overrides** Inspector array accepts profile ID and nonnegative finite weight. Leave it empty to use built-in defaults; add only the IDs whose weights need tuning, without copying operation definitions. Overrides apply to custom Inspector profile arrays too. Unknown IDs, duplicate IDs (case insensitive), missing IDs, and invalid weights fail clearly on reset. Zero removes a profile from ambient selection but leaves `spawn <profileId>` available. Changes take effect on reset; the run recorder stores effective weights, and a seed plus unchanged configuration replays the same plan and ID streams. Explicit queues still dispatch with ambient disabled. No independent hostile clock, ramp, or population cap was introduced.

This phase gives Connections a continuous benign traffic rhythm. Packet remains an independent game and its traffic classes are unchanged.

## Ownership and spawn pipeline

`ConnectionTrafficDirector` owns a local seeded `System.Random`, an ambient cadence, generated profiles, a queue of fully specified `ConnectionSpawnPlan`s, and stable same-time insertion order. Every ambient arrival and externally submitted plan calls `QueueSpawnPlan`; due plans are converted into definitions and registered through `SimulationHost.RegisterConnection`. The director is called from the host's fixed simulation step before resource allocation. Ambient generation can be disabled without suppressing queued plans. A plan includes its scheduled simulation time, unique short ID, explicit route and origin, target, profile ID, purpose, and concrete operation WORK and LOAD. Future event or infection producers can construct a plan with an internal origin and valid physical route, then call the same queue API. They are not implemented here.

`SimulationHost` validates node membership, route links, uniqueness, finite positive operations, and operation kinds. It owns active states, LOAD allocation, WORK, stage transitions, resolution timestamps and reasons, and inspection history. Completed generated states leave the active array after the allocation step and keep a history reference. `kill <id>` removes active ownership immediately and publishes released node demand; peers receive new allocation on the next step. `ConnectionResolved` exposes Completed and Killed outcomes. No scoring or FLOW effect is attached.

Threats V0 Slice 1 adds development-only `spawn <profileId>` through the same profile-to-plan builder and `QueueSpawnPlan` path used by ambient generation. The command reports a queued ID or unknown-profile error. Queued plans dispatch even with ambient generation disabled, and authored witness mode suppresses ambient generation while retaining explicit queue dispatch. Slice 2 adds `spawn delayed-threat` to that catalog; it uses the same queue and registration path. Manual spawns are not a Level Director or a scheduling language.

Slice 3A allows connection- and operation-scope behavior definitions to travel through the existing profile-to-concrete-plan path. The default profile catalog supplies none; the behavior witness queues explicit plans to exercise the foundation without changing ambient traffic or adding a threat profile. A Connection Plan describes intended operations and behaviors, while `ConnectionSpawnPlan` remains the scheduled concrete arrival. See the [behavior foundation](connections-behavior-foundation-v0.md).

Slice 3B adds three manual-only, zero-ambient-weight profiles to that same default catalog: `spiking-threat`, `spiking-benign`, and `overload-demo`. The first two use the same SPIKING LOAD behavior but differ in internal hostility and operation-completion delivery. The OVERLOAD example has no delivery. Existing ambient weights and profile definitions are unchanged; these profiles are observation tuning, not a rebalance.

The Packet game's separation between procedural traffic, concrete spawn plans, and level events informed this seam. Its tick schedules, modifiers, threat generation, and runtime code are not reused. Connections uses its existing simulation clock and LOAD allocator.

## Modes and tuning assumptions

`Connections.unity` defaults to Generated mode. The host Inspector can switch to Authored Witness mode for the existing c1/c2/c3 demonstration; the Resource and Geometry Witness menu checks select that mode during their run. Reset clears time, queues, history, and ID reservations, then replays the selected mode from zero. The generated mode does not start the authored connections.

The initial profile catalog is the director's default when no Inspector profiles are supplied. Each stage independently samples its configured LOAD and nominal duration, then sets `WORK = LOAD × duration`. These are initial playtest ranges, not fixed gameplay rules:

| Profile | Target | Operations | Desired LOAD | Nominal duration |
|---|---|---|---|---|
| Record Retrieval | DB | READ | 1–2.5 | 40–70 s |
| Record Indexing | DB | WRITE → READ | 1.5–3, then 1–2.5 | 20–35 s per stage, 40–70 s total |
| Customer Authentications | AUTH | EXECUTE | 1–2.5 | 40–70 s |
| Application Updates | API | WRITE → READ | 1.5–3, then 1–2.5 | 20–35 s per stage, 40–70 s total |
| Quick Record Lookup | DB | READ | 0.5–1.5 | 4–8 s |
| Basic Threat (`basic-threat`, manual only) | DB | WRITE with completion delivery | 12 | 20 s (240 WORK) |
| Delayed Threat (`delayed-threat`, manual only) | DB | READ without effect, then WRITE with completion delivery | 2, then 12 | 8 s (16 WORK), then 20 s (240 WORK) |

Both threat profiles have ambient weight zero. The delayed profile's READ is deliberately short for manual review, and its WRITE uses the same authored high-demand stage definition as `basic-threat`. Its actual duration grows under contention because WORK uses allocated LOAD.

Relative ambient weights of the five benign profiles are 1, 0.8, 1, 0.8, and 0.35 respectively. The seed is 1701, grace period 3 s, interval 13.5 s with ±1.5 s jitter, and ordinary origin EXT1. Routes are found from the configured physical topology in stable link order. Node capacities come from the scene, currently 10 LOAD for each node. The optional `demandtest` command queues one 10–12 LOAD READ to DB through the same pipeline; `QueueHighDemandWitness(..., false)` covers the 7–9 LOAD range. Neither the demand witness nor either threat belongs to the ambient mix.

The arrival cadence does not observe active population. Completion time depends on allocated LOAD and may increase during contention. There is no target concurrency, replenishment, or gameplay cap. A congested network can accumulate more connections; tuning should be adjusted after playtesting rather than hidden by population control.

## Validation and limits

Use `Tools/Connections/Run Traffic Witness`, `Run Resource Witness`, and `Run Geometry Witness`. The traffic witness checks seeded replay, routes, duplicate IDs, explicit arrivals with ambient off, single and multi-stage completion, inspection history, a 12-plan burst, proportional LOAD, kill resolution and release, plus manual benign/threat lifecycle, independent deliveries, and reset/replay. Play Mode at 16:9 is still needed to assess cadence and congestion, overlapping labels and identity cycling, arrivals without path resets, READ/WRITE/EXECUTE effects, `inspect` history, `kill`, `spawn`, `demandtest`, and prompt focus.

The profile catalog and cadence are provisional. Slice 1 has internal hostile classification and an infection-delivery occurrence, but no persistent infection, level event scheduler, scoring, FLOW, stage-specific target, or routing action. Completed inspection history persists for the run and is not yet bounded. The high-demand command is a mechanical witness, not a threat designation.
