# Connections Inspect V2 — compact and verbose

**Status:** Implemented on `feat/connections-inspect-v2` for review. This is a Connections terminal presentation change; it does not alter simulation, allocation, plan data, or information access.

`inspect <id> [id ...]` and its `i` alias produce compact cards by default. `inspect -v <id> [id ...]`, `inspect --verbose <id> [id ...]`, and the equivalent `i` forms produce verbose cards. A command accepts any number of IDs. The output repeats its authored card element within one scrollable result; IDs are resolved and checked for duplicates before the result is appended. Missing IDs and invalid flags return usage or flag feedback.

Compact cards show the connection ID and claimed purpose, a width-aware operation timeline, and a fixed right-aligned badge for **current effective requested LOAD**. They omit the status explanation, allocation detail, WORK, activity, ETA, and progress bar. Verbose cards retain those details and use `ALLOC allocated/requested` in the status line to keep the requested LOAD badge visually primary. Completed or killed connections remain inspectable in either mode; their badge reads `LOAD 0` because they make no current demand.

The timeline uses outlined pills for every visible element. The active operation carries the existing performance color. The immediately previous completed operation appears with a muted checkmark when it fits; older completed stages become `✓ +N`, and future stages become `+N`. The row reserves badge space before measuring pills. It can shorten a current or previous label to its operation kind, then collapse groups, without changing the underlying operation plan or history. Six-stage and narrow-width cases are covered by the deterministic witness. The badge uses quiet color at normal speed and existing slowed/stalled colors under contention; high demand alone is not a threat signal. Effective LOAD updates from OVERLOAD and SPIKING are read from the same simulation state as allocation.

The card now has a small additional content inset, with more space above and below each entry. Its connection ID, operation, and LOAD pill borders use `ConnectionsPill.mat`. That shared material applies the same fragment-coverage idea as the physical/logical line treatment in [Connections line rendering](../Review/LineAntialiasing/README.md), with a rounded-rectangle distance calculation instead of line-rectangle coordinates. The line material itself cannot interpret the pill mesh. `PillGraphic` retains its polygon fallback for UI without the pill material; the material's fill color is shared, while corner radius, border thickness, and outline color remain per-pill. The Connections scene Canvas supplies the TexCoord1 channel used by the pill graphic.

`Assets/Editor/InspectV2Witness.cs` checks command modes, five-ID compact and verbose cards, first/middle/final and completed/killed timelines, wide and narrow six-stage packing, badge alignment, live modifier LOAD changes, and the authored pill material bindings. `Assets/Editor/InspectV2Capture.cs` generates the [16:9 Editor review images](../Review/ConnectionsInspectV2/README.md) from the scene simulation and authored prefab. These captures preview UI composition; interactive Play Mode review remains necessary for focus, scrolling, and live traffic density.

## Fitted pill follow-up — gameplay QoL branch

The later gameplay QoL cleanup replaces the original fixed 126-unit LOAD badge with a text-measured pill. Its right edge stays aligned to the card inset, while its actual width is reserved before packing the operation timeline. Every LOAD label uses one decimal and an invariant period (`1.9`, `2.0`, `2.1`, and retired `0.0`). The monospace digits keep the width stable within one digit count; adding a digit resizes the badge and repacks the timeline.

The shared authored token prefab gives active, completed, future-count, and LOAD pills centered labels and 12 units of outer horizontal padding on each side. A completed pill additionally reserves the authored 16-unit checkmark plus a 6-unit internal gap, keeping the combined checkmark/text group centered. Existing 40-unit heights, borders, colors, and narrow-width shortening remain. The same measurements drive preferred widths and timeline fit decisions. Compact, verbose, completed, killed, and canceled cards share these rules. This changes presentation only.

The extended Inspect V2 Witness checks padding/centering, one-decimal LOAD under a comma-decimal locale, stable `1.9 → 2.0 → 2.1` widths, live one-/two-digit badge resizing, narrow cards, and completed/killed/canceled output. See the [Editor previews and manual review steps](../Review/ConnectionsInspectPillFit/README.md).
