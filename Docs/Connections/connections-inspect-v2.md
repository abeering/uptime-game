# Connections Inspect V2 — compact and verbose

**Status:** Implemented on `feat/connections-inspect-v2` for review. This is a Connections terminal presentation change; it does not alter simulation, allocation, plan data, or information access.

`inspect <id> [id]` and its `i` alias produce compact cards by default. `inspect -v <id> [id]`, `inspect --verbose <id> [id]`, and the equivalent `i` forms produce verbose cards. The existing authored inspect block supports up to two IDs per command. Missing IDs, excess IDs, and invalid flags return usage or flag feedback.

Compact cards show the connection ID and claimed purpose, a width-aware operation timeline, and a fixed right-aligned badge for **current effective requested LOAD**. They omit the status explanation, allocation detail, WORK, activity, ETA, and progress bar. Verbose cards retain those details and use `ALLOC allocated/requested` in the status line to keep the requested LOAD badge visually primary. Completed or killed connections remain inspectable in either mode; their badge reads `LOAD 0` because they make no current demand.

The timeline uses outlined pills for every visible element. The active operation carries the existing performance color. The immediately previous completed operation appears with a muted checkmark when it fits; older completed stages become `✓ +N`, and future stages become `+N`. The row reserves badge space before measuring pills. It can shorten a current or previous label to its operation kind, then collapse groups, without changing the underlying operation plan or history. Six-stage and narrow-width cases are covered by the deterministic witness. The badge uses quiet color at normal speed and existing slowed/stalled colors under contention; high demand alone is not a threat signal. Effective LOAD updates from OVERLOAD and SPIKING are read from the same simulation state as allocation.

`Assets/Editor/InspectV2Witness.cs` checks command modes, two-ID cards, compact and verbose content, first/middle/final and completed/killed timelines, wide and narrow six-stage packing, badge alignment, and live modifier LOAD changes. `Assets/Editor/InspectV2Capture.cs` generates the [16:9 Editor review images](../Review/ConnectionsInspectV2/README.md) from the scene simulation and authored prefab. These captures preview UI composition; interactive Play Mode review remains necessary for focus, scrolling, and live traffic density.
