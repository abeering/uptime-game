# Payload Launcher V0

**Scope:** Connections implementation, November 4, 2026. This is a manual playtest slice in both Connections scenes. It does not set a general rule for adversary pacing or Payload sources.

`spawn payload-launcher` queues an ordinary-looking hostile logical connection through the existing profile path. Its claimed purpose is **Application Updates** and its single EXECUTE operation targets API, requesting 3 LOAD for 60 WORK (20 seconds at full allocation). The connection can be inspected, blocked, or killed through the existing commands and allocator. The profile has zero ambient weight.

Completing that operation publishes the typed `PayloadLaunch` effect and creates exactly one Steady Payload at API, targeting adjacent DB. It appears red from the start of its final-hop establishment, then uses the existing 1.2-second establishment and seeded 5–6-second final traversal. The player can therefore kill the launcher before completion or intercept its Payload at DB afterward. The 8-second interception window, 15-second cooldown, 4-LOAD defense demand, Payload infection delivery, and both interception matching modes are unchanged. Killing or canceling the connection before the operation completes prevents the launch.

The completion effect is appended to the enum, with a typed destination and motion profile copied through profile, spawn plan, definition, and occurrence. Launch validation requires a hostile connection and a physical link from its target node to the destination. The recorder retains the operation's launch specification in the profile and spawned definition, plus a `payload_launched` receipt with connection ID, operation index, Payload ID, origin, destination, and motion profile. Existing `payload_created` and delivery receipts continue the Payload side of that lineage. Seeded replay preserves Payload timing. While a launcher is pending, coarse scripted simulation steps advance at fixed-step cadence so the Payload starts at the operation completion time and continues to move during the remaining step.

Validation: `PayloadLauncherWitness` checks both scenes for the typed profile, kill suppression, one-hop red appearance, exactly-once launch, targeted and node-wide interception, missed delivery to DB only, recorder lineage, and coarse/fine replay. Existing Payload, traffic, infection, recorder, and recon witnesses remain regression checks. Scripted Play Mode captures and the exact run results belong in `Docs/Review/ConnectionsPayloadLauncherV0/README.md`.

Manual Unity review: open each Connections scene in Play Mode at 16:9, run `spawn payload-launcher`, inspect the ordinary connection, then separately try killing it before completion and intercepting its red Payload at DB after completion. Check terminal command focus, the API-to-DB red path and node status, and the result when interception is delayed until after impact.
