# Company Feedback V0 — Slice 1

**Scope:** Connections implementation on `main` at `74c4401` (November 3, 2026). Packet is unchanged. This slice applies the human-consequence direction in [notifications](../Design/notifications.md) to the existing [Text Communications V0](connections-text-communications-v0.md) surface. It does not settle that design's broader cue, escalation or scheduling proposals.

Both playable Connections scenes reference one `Northstar Market` company definition. It provides a stable company ID, display name, Customer Support and Operations identities, and three short authored lines for each of two response categories. No portraits are required; the existing neutral avatar fallback is used.

`CompanyKillFeedback` listens to `SimulationHost.ConnectionResolved`. It accepts only `Killed` resolutions with `TerminationCause.Player` and authoritative `IsHostile == false`. `ProfileId == "order-submit"` selects a checkout response from Customer Support; every other benign profile selects a generic Operations response. The claimed purpose is never trusted for legitimacy. This is a deliberate fallback for authored and older profiles as well as the other current e-commerce purposes.

An accepted event schedules one message after one simulation second. A pending message suppresses further kills; successful delivery starts a 12-simulation-second cooldown. This keeps rapid multi-kills to one reaction. Line selection uses a private deterministic random stream with fixed scene seed and does not consume generation randomness. Reset or disable clears the pending event, cooldown and response stream. Delivery calls `TextCommunicationDirector.PushMessage` as an instant message; it does not touch input or Escape state. A failed delivery remains pending and can retry on a later fixed step while the surface is available.

The response is qualitative feedback only. It does not change Health, LOAD, traffic, scheduling, infection, scoring or run progression. Ordinary completion, hostile kills and non-player cancellations do not complain. There is no slowdown feedback, event spawning, adversary response, video call, Level Director or company selection.

## Review

Run `Tools/Connections/Run Company Feedback Witness (Play Mode)` in each of `Connections.unity` and `ConnectionsAdvanced.unity`, using `-witnessScene ConnectionsAdvanced` for the second batch invocation. The witness checks scene/asset references, one killed benign order submit, another benign purpose, a hostile order-submit kill with the same claimed purpose, ordinary benign completion, rapid kills/cooldown, and reset before delivery. Existing Text Communication and Network Health witnesses cover the notification surface and gameplay invariants.

On November 3, 2026, Unity 6000.3.11f1 compiled an isolated project copy. The Company Feedback Play Mode witness passed in both scenes: expected one Support IM for the order kill and one IM for five rapid kills, observed one in each case; generic fallback, hostile exclusion, ordinary completion, cooldown and reset checks also passed. `TextCommunicationWitness.CheckBindings` passed across both scenes, and the existing Network Health and Traffic witnesses passed. The existing render-dependent Text Communication Play Mode witness did not reach its assertions in this batch environment; runs with and without `-nographics` stayed in Unity render initialization and were stopped. No interactive keyboard or 16:9 reading review was performed.

For human Play Mode review at 16:9 in each scene: start generated traffic; use `spawn order-submit` and kill its displayed ID while the connection is live; watch for one Support IM about checkout after roughly one simulation second. Repeat with `spawn inventory-sync` after the cooldown to see Operations' generic fallback. Try `spawn order-submit obj:delivery` and kill it; no company complaint should follow. Type a draft command during message arrival and verify text, cursor/focus and Escape behavior remain intact. A burst of `kill` IDs should leave at most one company response. For reset, stop and restart Play Mode before the one-second reaction delay elapses; no prior-run response should appear. The authored Witness mode can be used to confirm older benign profiles fall back to Operations.
