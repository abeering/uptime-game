# Connections — Network Health V0

**Lifecycle V1 update (October 25, 2026):** Health is connection-only. Blackout no longer has an outage drain or direct application penalty. Connecting attempts have no service deadline or per-second service impact. Established legitimate connections retain the slowdown and overdue rules below. A benign Killed attempt costs 10 and a benign Canceled attempt costs a provisional 5, once per resolution, whether it was Connecting or Active. Hostile terminations cost zero. Recovery can continue while Blackout remains active if no legitimate service is degrading or being canceled. See [Lifecycle V1](connections-lifecycle-v1.md) for route timing and receipts.

**Compact-only presentation update (October 31, 2026, after merged PR #69):** The expanded Health tray and its Tab binding have been removed, including the tray-only aggregate labels, peak LOAD calculation, recent-event text, focus restoration, and dynamic terminal inset. Both scenes keep the authored full-width 52-unit status strip and 8-unit gutter above fixed terminal and network panes. No replacement condition indicators are introduced. A later [global tool readiness strip](connections-global-tool-readiness-v0.md) uses the bar's right side. The simulation still retains its existing Health facts for internal consumers and recording.

**Scope:** Connections implementation only. This is a provisional, live service instrument for the current small scenario. Packet FLOW and Packet scoring are separate. Performance, human notifications, and run endings remain future designs.

**Health bar display fix (gameplay QoL review branch, October 27, 2026):** The authored fill is a sprite-less rectangular Image. Unity ignores `Image.fillAmount` for sprite-less images, so the prior bar stayed visually full even as the numeric Health changed. The panel now sets the fill rectangle's horizontal anchor to Health / 100, matching the existing inspect progress-bar approach, and the prefab uses Simple image mode. Health simulation and tuning are unchanged. The Network Health Witness checks visible width at full, damaged, recovering, and zero Health.

**Presentation follow-up on the same branch:** The authored bar is 18 scene units tall (previously 12) and 40 units wider, with its spacing centered between `HEALTH 100` and a reserved signed two-digit rate such as `-11.11/s`. The rate's right edge is unchanged, and fractional Health text still clears the bar. In Play Mode, width uses an exponential lerp in unscaled time, with an Inspector speed of 10 (about 95% of a change in 0.3 seconds); a speed of zero disables easing. The numeric Health and signed rate remain authoritative and immediate. The bar stays muted orange while Health is draining, including rates below the numeric display precision, or while an instantaneous loss is visibly settling even if recovery has already begun. Otherwise it is teal. Actual Health strictly below the Inspector's `criticalHealthThreshold` (default 25) makes the bar red in every state, before the animated width catches up. Colors are serialized on the prefab. First display, re-enable, and a backwards simulation-clock reset snap to current Health. Editor rendering snaps for authoring. The existing Health Witness additionally checks spacing, repeated losses, smoothing convergence and frame subdivision, color precedence, recovery, threshold configuration, and snapping. See the [prefab state preview](../Review/ConnectionsHealthBar/README.md). This is presentation only.

Network Health starts at 100 and stays within 0–100. The simulation host updates it once per fixed step from the allocator's actual grants. Only legitimate active connections contribute service damage. A connection's fixed deadline is set at activation from the sum of each operation's authored WORK / authored LOAD, multiplied by a tolerance. Later behavior modifiers do not move the deadline. Before its deadline, a legitimate connection below the substantial slowdown threshold contributes drain proportional to its LOAD shortfall. After its deadline, a larger drain replaces the slowdown drain and rises with time overdue. Passive recovery occurs only when no degradation is present; it never offsets concurrent drain. Killing a legitimate connection applies one immediate penalty. A hostile connection does not contribute direct service or kill damage, but its LOAD can indirectly reduce legitimate grants. An infection-delivery occurrence alone has no Health effect.

The simulation retains each connection's deadline, nominal duration, whether it was substantially slowed or late, existing resolution reason, and resolution timestamp. Slowed and overdue counts include all active connections, including hostile ones; resolution removes them from current counts while preserving lifecycle history. Completion applies no second duration penalty. A zero value latches `Failed`; this phase does not end a run. The read-only snapshot exposes value, actual signed net rate, recovery and degradation components, slowed/overdue counts, legitimate impact evidence for internal consumers, recent discrete events, and failure state. The Health portion of the permanent compact panel shows the clock, authoritative Health value, animated Health bar, and actual signed rate. Slowed/overdue counts, impact evidence, recent events, and failure state remain in the simulation snapshot and recorder; the removed expanded tray no longer presents them.

## Provisional Inspector tuning

| Parameter | Initial value |
|---|---:|
| Deadline tolerance | 1.5 × nominal plan duration |
| Shortfall drain | 0.25 Health/s at full LOAD shortfall, per substantially slowed legitimate connection |
| Overdue drain | 0.50 Health/s per overdue legitimate connection |
| Overdue escalation | +0.02 Health/s per additional second overdue |
| Recovery | +0.35 Health/s when below 100 and no degradation is present |
| Incorrect legitimate kill | −10 Health once |
| Substantial slowdown threshold | satisfaction below 0.98 |

The 24-hour clock is display-only. Its serialized start is 09:00, end is 17:00, and mapping is one clock minute per simulation second. The end time is a configuration marker for later shift design; it does not trigger progression or evaluation. A future design may tint the clock for early-, middle-, and late-shift pacing, but V0 keeps neutral styling.
