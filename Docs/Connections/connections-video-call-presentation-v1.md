# Connections — Video Call Presentation & Soft Placement V1

**Scope:** Connections presentation, based on merged PR #72 (`main` at `ddb955b`). The [V0 call/Escape contract](connections-video-calls-escape-v0.md) still defines call lifecycle, input protection and dismissal. This pass changes the authored interior, Escape-state colors, open-time placement and developer overlap testing. The [workspace design in PR #67](https://github.com/abeering/uptime-game/pull/67) remains broader design context; notifications, menus and story scheduling are not implemented.

## Video-first presentation

The review refinement of `VideoCall.prefab` uses a 520×400 reference rectangle, nested shared 40-unit titlebar, dynamic caller identity, and shared two-unit frame. Its 488×274.5 camera region is exactly 16:9 and retains approximately the same feed area as the initial 536×250 region. Caller sprites preserve aspect ratio; the same enlarged region uses the existing static texture when no portrait is supplied. The optional Animator controller and `IsTalking` bool continue to follow unscaled subtitle disclosure.

An 88-unit translucent dark overlay sits eight units inside the lower feed edges. The scrim alpha is 0.60, softened from the initial 0.80. Its high-contrast 18-unit text has 16-unit horizontal and ten-unit vertical padding, approximately three lines per page. TMP Page overflow and the existing typewriter advance to the page containing the newest disclosed character. Completed dialogue stays on its final page until the call ends. There is no new subtitle timing, skip action or automatic hang-up.

The slim bottom strip authors a centered 116-unit group: a 40-unit circular Unity UI Image, its aspect-preserving handset child, a 12-unit gap, and a TMP `[ESC]` keycap. The circle uses Unity's existing plain circular UI sprite. The handset uses the supplied `Assets/Images/phone.png`, imported as one uncompressed UI Sprite with transparency and no mipmaps. Its PNG pixels are preserved. No character artwork or active/inactive icon variants are added. No control is clickable or a raycast target. The titlebar also retains `[ESC] HANG UP`, with reserved caller-title space and ellipsis for long identities. The feed caption remains removed.

`SetEscapeTarget(bool)` drives both titlebar and bottom indicators from the same target boolean; the titlebar label shares the bottom keycap color. The current call target uses a muted red circle, near-white handset and pale red keycap. An older call stays fully visible and active with a gray circle, muted handset and gray keycap while CLEAN owns Escape. Only these indicator tints change: video, subtitle progression and animation continue. Both remain visible in subdued gray while the call is inactive as an Escape target. Disabling the coordinator also removes the highlight. CLEAN retains its existing active `[ESC] CANCEL` label. Escape input still has one authority.

## Placement on opening

Each NetworkPanel authors one small `ConnectionsWindowPlacement` helper bound to the two windows and their important content rectangles. Calls prefer the upper-right home, 24 units from the right and 64 from the top. CLEAN resolves its node through `CleanSession.Target.View`, using the real `SimulationHost`/`NodeResources` binding; no node names or topology coordinates are hardcoded.

The helper evaluates a fixed, deterministic list. CLEAN considers positions around the node, the node itself, and viewport fallbacks. Calls consider home, nearby horizontal/vertical alternatives and viewport fallbacks, with two additional adjacent positions just below or left of an existing CLEAN window. Candidates clamp into the network content area, leaving 12-unit side/bottom margins and the permanent titlebar plus 12 units above. If a viewport is smaller than a window, centering minimizes unavoidable overflow; no resizing or pane reflow is introduced.

The provisional score uses squared distance from the node/call home at weight 0.08, whole-window intersection area at 0.03, and intersection with important existing content at 10. Protected rectangles are the call feed (including subtitles) and bottom control group, plus CLEAN's title, process body (including PID/CPU headings), PID input and Escape label. PID bounds remain protected during the splash so an arriving call cannot occupy the upcoming input region. Ordinary frame, corner, header-edge and unused-margin overlap is cheap; useful-content obstruction is expensive. There is no reserved upper-left exclusion zone. Future textual communications may prefer that corner, but this phase adds no notification surface.

Placement happens once when a window opens, before its existing newer-on-top sibling ordering. The older window never moves because of an arrival, dismissal, target change or traffic. Reopening recomputes placement from current node/view and viewport geometry. Windows do not chase nodes, and placement never changes node positions, paths, permanent panes, Escape order, typing focus or simulation state. It is a small candidate heuristic for two surfaces, not a guarantee of zero overlap under all viewport constraints or a desktop manager.

## Delayed developer sample

Editor/development builds support `calltest` immediately or `calltest delay=5`. Delays accept invariant decimal seconds from 1 through 30 and use unscaled real time. A terminal allows one pending test; duplicate pending/immediate requests are rejected. On expiry it calls the existing `TryStartSampleCall()` once. An already active call is preserved by that API; there is no replacement or queue. Terminal disable/destruction/scene shutdown cancels pending work. Arrival writes no terminal output and performs no focus transfer, allowing a PID draft and selection to remain intact. This is explicitly labeled developer sample content, not a network event or narrative scheduler.

## Validation and review

The updated Escape/Video Call witness checks authored bindings, feed/subtitle/control presentation, the same phone sprite in both tint states, actual node-based placement, fixed older windows, delayed arrival/duplicates/cancellation, focus and Escape invariants, long dialogue, portrait/talking hooks, and generated traffic. `-witnessWidth` and `-witnessHeight` select a fixed Canvas render viewport for the **whole** Play Mode run, including placement. `-capturePath` saves that size. It no longer resizes only when taking a picture. These are scripted Play Mode Canvas captures; physical keyboard/IME and the native Game view require human review.
