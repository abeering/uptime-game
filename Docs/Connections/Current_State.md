## Playable slice and simulation

The scene has an authored four-node, three-physical-link topology: EXT1–API, API–DB, and API–AUTH. A **logical connection** has a stable short ID and a route through that graph. Physical links and logical paths have separate view responsibilities. The scene's serialized `runMode` is **Generated**; Authored Witness mode retains c1/c2/c3 for focused review and tests.

`SimulationHost` owns one fixed-step simulation clock, active connection state, inspection history, and resolution. `ConnectionTrafficDirector` uses separate seeded schedules to queue benign coverage and hostile arrivals, then registers concrete plans through the host; queued plans can also be supplied explicitly. Both ambient streams select from [six ecommerce purpose templates](connections-purpose-anomaly-generation-v0.md) with their eligible targets. Each purpose samples normal LOAD and WORK independently, then the hostile stream composes a LOADER or DELIVERY attempt while the benign stream may generate an outlier. Inspector weight overrides tune the canonical purpose mix without copying built-in operations. The earlier ten profiles have zero default ambient weight and remain available through explicit `spawn <profileId>` and witnesses; ambient generation now selects canonical PURPOSE templates only. Rates and timing are playtest tuning, not balanced game rules. Completed or killed generated connections leave active ownership but remain inspectable for that run. The [traffic document](connections-arcade-traffic-v0.md) preserves prior phase provenance.

The current allocator grants **target-node LOAD** proportionally when requests exceed capacity after baseline LOAD. Transit nodes and physical links are route geometry in this model; they are not CPU/disk/memory/link-bandwidth allocation constraints. Productive WORK advances by allocated LOAD × effective WORK rate multiplier × simulation seconds; existing plans have a neutral 1× factor. An operation may be READ, WRITE, or EXECUTE and have its own WORK and desired LOAD. Authored multi-operation arcs advance to the next operation on the following fixed step, retaining the connection ID, route, target, and path; only final completion resolves the connection. See [LOAD](connections-arcade-load-v1.md) and [operation arcs](connections-arcade-operation-arcs-v1.md). The current arcs do not change target or route between operations.

Presentation consumes simulation state. Node LOAD bars show requested LOAD / capacity with capped fill and threshold colors; they do not separately show allocated LOAD, though the simulation tracks requested and allocated values independently. Overloaded color is not a threat label. Path pulses express WRITE toward the target, READ toward origin, or EXECUTE locally, while speed/satisfaction treatments reflect allocation. The terminal has structured inspect output with an operation timeline and retains keyboard input. `inspect`/`i` default to [compact cards](connections-inspect-v2.md) with ID, purpose, timeline, and current effective requested LOAD badge; `-v`/`--verbose` adds performance status and any contention reason, WORK, activity, and ETA. Any number of IDs can be inspected in one command, including retained completed or killed history. Inspect cards have a full-height identity rail and a large, identity-colored ID pill at upper left; the purpose, operation timeline, and LOAD pill sit to its right, with verbose details below. The old horizontal TitleBar behind the purpose is removed, and verbose status omits the numeric ALLOC fraction. The ID, operation, and LOAD pill borders use a rounded-rectangle antialiasing material derived from the line-rendering coverage approach. `kill|k <id> [id ...]` independently attempts each unique ID in order, reporting failures without stopping later kills; successful kills release LOAD and retain the existing Health penalty and recorder effects; `demandtest` queues a deliberate high-demand mechanical witness. Development-only `spawn <profileId>` queues any configured profile, including `basic-threat`, `delayed-threat`, `spiking-threat`, `spiking-benign`, and `overload-demo`, independently of ambient generation. Inspection and command entry are immediate; consequences progress in simulation time. [Terminal and inspect cleanup Editor captures](../Review/ConnectionsTerminalInspectCleanup/README.md) show compact and verbose cards, multi-ID results, and a completed connection at 16:9. They are Editor previews, not Play Mode screenshots.

Slowed and overdue observations include all active connections, while hostile traffic causes no direct Health penalty. Zero latches failure without ending the run. A compact clock/Health row with signed rate sits above the terminal; TAB expands the same instrument to show aggregate conditions, peak requested/capacity node LOAD, and recent events while keeping the terminal and topology visible. Terminal history stays bottom-anchored above the persistent prompt on resize. The display-only 24-hour clock has configurable shift bounds and simulation-time mapping; shift progression and Performance scoring are not implemented. The model and values are provisional.
