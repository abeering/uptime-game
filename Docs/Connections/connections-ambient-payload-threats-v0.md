# Connections — Ambient Payload Threats V0

**Scope:** Connections implementation, November 5, 2026. This integrates the existing Payload Launcher and Payload Spawner into Advanced ambient generation. Their movement, infection, interception, scan, CLEAN, and Packet behavior are unchanged.

The existing 30-second mean hostile opportunity clock now chooses among ordinary hostile connections, Reconnaissance, external Payloads, Worms, and Payload Launchers at provisional Advanced weights **4:2:2:1:1**. The fifth outcome builds the existing `payload-launcher` profile at the opportunity's scheduled time and queues it with source `ambient_payload_launcher`. It retains the authored Application Updates claim, API target, one EXECUTE operation, and API-to-DB Payload launch only after WORK completion. The four-node scene gives this activity zero weight. A zero fifth weight leaves the prior four-way selection boundaries intact.

Generated DELIVERY/INFECTOR plans in Advanced now choose Phantom LOAD, Blackout, connection Spawner, or Payload Spawner at provisional weights **1:1:1:1**. Composition supplies the Payload Spawner's existing 20-second default cadence, which starts after successful installation rather than at selection. Reconnaissance follow-up INFECTORs use the same choice. The connection Spawner's children retain their original three-kind infection selection, even though they share the plan composer. The four-node scene gives Payload Spawner zero infection weight. Manual `spawn payload-launcher` and `infect <node> payload-spawner [cadence]` remain available.

The run recorder stores the fifth activity weight in run metadata and each `hostile_activity_selected` event. Launcher selection receipts retain its generated connection ID, profile, operation index/kind/effect, scheduled time, and the same identity in `hostile_opportunity`; the `plan_queued` source distinguishes it from manual spawning. `payload_launched` links the original operation to the new Payload ID. Infection selection is captured in the generated plan trace and typed final operation; `infection_applied` records the carrier, while `payload_spawner_attempt` links periodic launches back to that infection and its source connection. Existing delivery, rejection, interception, and cleaning receipts continue the lifecycle.

The focused `AmbientPayloadThreatWitness` checks both scene defaults, the scheduled ambient Launcher and kill suppression, generated INFECTOR cadence and CLEAN, nonrecursive connection Spawner children, hostile toggles, replay, and four seeded 600-second Advanced runs. The [review evidence](../Review/ConnectionsAmbientPayloadThreatsV0/README.md) records the observed counts and scripted Play Mode frames. These distributions are playtest evidence, not new difficulty targets.
