# Independent Benign Demand V0 — Unity experiment

November 22, 2026. Connections implementation only, based on unmerged PR [#124](https://github.com/abeering/uptime-game/pull/124), commit `7cec0ae7e2c0b363fa07613c99cc4b3e2898dcf3`. Branch: `experiment/connections-independent-benign-demand-v0`. This experiment targets that feature branch; main, #124 and #115 are not changed or merged.

**Recommendation: revise and playtest the experiment; do not adopt it as canonical yet.** Independent arrivals remove the occupancy feedback, and ordinary delayed WORK can remain after a source is killed. The tested rates do not reliably produce the desired combination of a comfortable healthy network and a substantial source-caused congestion tail. Faster demand also changes the meaning of the existing WORK quotas considerably. No allocator, enemy, CORE, Overclock, credit, ending or quota rule was adjusted to make the hypothesis work.

Read [results](RESULTS.md), [generated measurement tables](measurement-tables.md), [validation and reproduction](VALIDATION.md), and the [runtime contract](../../Connections/connections-independent-benign-demand-v0.md). The graphs and gzip files contain actual Unity execution, not the earlier external Python simulation.

## Implementation and evidence

One enum and one isolated exponential clock in the existing `ConnectionTrafficDirector` select population-responsive or independent arrivals. Both use existing PURPOSE generation, concrete-plan queue, host registration, lifecycle, allocator and accounting. The population policy remains the serialized zero/default in both untouched canonical scenes. The comparison seam is temporary; its removal points are documented in the contract.

There is no new admission queue or occupancy cap. Independent requests have separate arrival/admission recorder events and snapshot totals. All measured independent requests were admitted; waiting and unadmitted counts were zero. The existing finite generated-ID pool is exercised separately and produces explicit recorded unadmitted failures when exhausted. Operational backlog means ordinary registered connections and their outstanding WORK, not fictitious queued customers.

- [192 controlled runs](controlled-runs.json.gz): both scenes, four seeds, healthy/30-second withdrawal/kill after ten active seconds/kill plus ordinary Overclock. Each scene compares the population baseline with five independent rates, including an empirical baseline-rate match. Diagnostic quota is unreachable; real CORE endings remain possible.
- [Controlled per-run CSV](controlled-summary.csv) and [summary JSON](controlled-summary.json): admission, active density, LOAD severity/duration, delays, recovery, CORE and WORK totals. Gzip retains per-second traces, per-node integrals and every completed operation measurement.
- [48 natural shifts](natural-runs.json.gz), [summary](natural-summary.json): six seeds, actual six-minute/900 or 1,200 quotas, ordinary mixed hostiles, unattended or bounded visible defense. Trial independent means: Small 8 seconds, Advanced 6 seconds.
- [Paired recovery plot](paired-recovery.png) and [healthy rate sweep](rate-sweep.png): generated from the saved Unity traces by [summarize.py](summarize.py). The script only analyzes data.
- [Deterministic checks](deterministic-checks.txt), [parent WORK checks](parent-work-checks.txt), [unchanged quota checks](parent-quota-checks.txt), [canonical scene parity](canonical-parity-checks.txt), [aggregate regressions](parent-regression-checks.txt), and [terminal/concession regressions](duel-concession-checks.txt). ## Human Unity review

1. Open this branch with Unity **6000.3.11f1**. Use `Assets/Scenes/Connections.unity`, then `ConnectionsAdvanced.unity`. Preserve local scene changes; use runtime Inspector edits and do not save experiment settings into the canonical scenes.
2. On the existing `ConnectionTrafficDirector`, first play the untouched `Population Responsive` policy. For a repeatable comparison, disable `Randomize Seed`, set seed 1701 (then 1702, 3141, 9001), select `Independent Demand`, set `Independent Benign Mean Seconds`, then restart. Restart after changing policy/rate.
3. Begin with **Small 8s / Advanced 6s** to reproduce the graphical/natural trial; use **Small 12s / Advanced 8s** for a gentler comparison, and **Small 6s** as a stress case. These are test settings, not approved balance. Avoid 4s as a starting point: legitimate traffic alone can cause CORE losses. The unchanged Inspector mean defaults to 8s when independent is selected.
4. Play complete quota-enabled shifts. Record ending, simulation time, confirmed WORK, node Integrity and whether decisions still matter before the quota ends. Compare the same seed under population-responsive demand. Do not infer threat balance from runs that end much earlier.
5. For recovery testing, temporarily set the host's runtime WORK target to 1,000,000 while retaining 360 seconds and Integrity. Use the reproducible controlled harness described in validation for the exact 12-LOAD fixture; ordinary developer `spawn <purposeId> obj:loader` can explore authored LOADER variants but does not promise the same fixture. Kill a known source with `kill <id>`, compare ordinary `overclock DB`, and observe after the 15-second boost expires. Check whether competing legitimate LOAD actually remains above available capacity, separately from delayed unfinished WORK.
6. At 1920×1080 and 1280×720, inspect busy connection bundles and moving labels; compare readable density with the population baseline. Use `inspect -v <id> ...`, scroll history, type successive commands, and verify input focus, terminal/network proportions, WORK strip and tool readiness. The automated captures verify focus state, not real keyboard/IME use or sustained playability at the measured density peaks.

Human testing, sustained high-density readability, real keyboard/IME input and Packet Play Mode remain outstanding. Packet code and scenes are untouched. Leave this PR draft and unmerged until review.
